# Image Thumbnail Generation

This document describes how Stash generates and stores image thumbnails.

## Thumbnail Generation

**Main file:** `pkg/image/thumbnail.go`

This file contains the `ThumbnailEncoder` struct that handles thumbnail creation. Key points:

1. **Libraries used:** It uses either `vips` (libvips) or `ffmpeg` to generate thumbnails - `vips` is preferred for better performance
2. **Default size:** 640px width (defined in `pkg/models/model_gallery.go` as `DefaultGthumbWidth`)
3. **Output format:** JPEG (`.jpg`)
4. **Skipped formats:** Animated images (GIF, animated WebP) are not thumbnailed

## Thumbnail Storage

**Path configuration:** `pkg/models/paths/paths_generated.go`

Thumbnails are stored in a `thumbnails` subdirectory within the generated directory. The path structure uses a 2-level directory depth based on the image checksum:

```
thumbnails/
  └── XX/
      └── XX/
          └── <checksum>_<width>.jpg
```

The thumbnail path is generated by `GetThumbnailPath(checksum, width)` at lines 80-82.

## Generation Task

**Task file:** `internal/manager/task_generate_image_thumbnail.go`

This task runs during library scans (if enabled in config). It:
1. Checks if thumbnail already exists (unless `Overwrite` is set)
2. Skips images smaller than the thumbnail size
3. Uses the `ThumbnailEncoder` to generate the thumbnail
4. Writes the result to disk using `fsutil.WriteFile()`

## API Endpoint

**Route:** `internal/api/routes_image.go:42` - `/thumbnail` endpoint serves existing thumbnails or generates them on-the-fly if not found on disk.

## Generated Directory

**Purpose:** Stores generated content like thumbnails, previews, screenshots, transcodes, and markers.

**Configuration:** `generatedPath` in config (default: `<config_dir>/generated`)

**Structure:**
```
generated/
├── thumbnails/    # Image thumbnails (e.g., <checksum>_640.jpg)
├── screenshots/  # Scene screenshots
├── vtt/          # Video preview sprites
├── markers/      # Scene markers
├── transcodes/   # Video transcodes
├── downloads/    # Download staging
├── tmp/          # Temporary files
└── interactive_heatmaps/
```

**Implementation:** `pkg/models/paths/paths_generated.go`

## Blobs Directory

**Purpose:** Stores binary content like performer images, gallery covers, and scene cover images.

**Storage Options:**
- **DATABASE** - Blobs stored directly in SQLite database
- **FILESYSTEM** - Blobs stored in filesystem at `blobsPath`

**Filesystem structure:**
```
blobs/
└── XX/
    └── XX/
        └── <checksum>
```
(2-level directory depth based on MD5 checksum)

**Configuration:** `blobsPath` and `blobsStorage` in config (default: `<config_dir>/blobs`)

**Implementation:** `pkg/sqlite/blob.go` and `pkg/sqlite/blob/fs.go`

## Key Differences

| Aspect | Generated | Blobs |
|--------|-----------|-------|
| Content | Thumbnails, previews, transcodes | Performer images, covers |
| Always filesystem | Yes | No (can be in DB) |
| Deletion | Cleaned via task | Auto-deleted when unreferenced |
| Lookup | By checksum | By checksum |
